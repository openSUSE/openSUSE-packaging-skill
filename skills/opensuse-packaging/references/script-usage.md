# Script usage — every flag and exit code

The exact usage of every bundled script: don't run `--help`. CI checks each line against the script's `--help`: long flags, `-x|--long` pairs, which flags take a value, and the exit codes (not positionals or the wording of meanings). Why each exists and the traps it encodes: `scripts/README.md`.

## Triage

- `my-packages.sh [--project PRJ] [--user OBSUSER] [--source obs|git|both] [--all-projects] [--show-source]` — `--all-projects` keeps Backports/Leap/SLFO/ALP; exit 0 listed · 2 usage or query failed
- `devel-packages.sh <devel-project> [<devel-project> ...]` — the Factory packages a devel project develops, `<package> <devel-project>` per line (names: `| cut -d' ' -f1`); exit 0 listed · 3 none · 5 search failed · 2 usage
- `outdated.py [--names FILE] [--project PRJ] [--repo REPO] [--ua UA] [--no-factory-check] [--no-anitya] [--no-forge] [--no-repology]` — names on stdin by default (`my-packages.sh` lines as they are); exit 0 full coverage · 3 a source lost, or no name found in --project · 2 usage, no names, or a line that is no package name
- `upstream-probe.py [pkg] [--spec FILE] [--url URL --version V] [--project PRJ]` — exit 0 CURRENT · 1 UPDATE-CANDIDATE · 3 SUSPECT · 2 usage or no verdict
- `distro-survey.sh <pkg> [factory-version]` — env `DISTRO_SURVEY_BUDGET`, `DISTRO_SURVEY_TIMEOUT`; exit 0 printed · 2 usage
- `factory-report.py [--days N | --since YYYY-MM-DD] [--project PRJ] [--top N] [--highlight USER] [--role-account ACCT]... [--json] [-o|--output FILE]` — HTML by default; exit 0 written · 1 geectl request search failed or no SRs · 2 usage

## Update and build

- `preflight.sh <pkg> [target-version] [--target-project PRJ] [--user U] [--from PRJ]` — `--from`: the project you will branch, STOP unless it is the devel project or what the devel package links to; a non-version target-version is a usage error; a package the target has under another spelling (`devel-of.sh` checks) is a STOP; a contributor's open SR or devel PR on a package you maintain (pr-guard's rule) is INCOMING, each `sr#ID`/`owner/repo#N` listed with its creator and its review stamp (`reviewed: BLOCK (key …)`, `not reviewed`, or for a PR whose head moved since `reviewed at an older head: review again`); your own request in flight is still a STOP; exit 0 PROCEED · 3 STOP · 5 INCOMING · 4 FORWARD · 2 a check failed or usage
- `build-summary.sh [repo-arch | flavor | root-name | root-path | logfile | --rpms DIR logfile | --list]` — `--rpms DIR`: a captured log's `.build.packages`, for the RPM checks; exit 0 green · 1 failed (also on a post-build check finding — unowned directories, a forbidden Requires — and when a built RPM requires a user()/group() its own scriptlets create and nothing provides) · 2 no log · 3 no verdict (also a green spec build whose RPM directory holds no source RPM, `.src.rpm` or `.nosrc.rpm`, or binary RPMs that cannot be queried: no rpm, or rpm cannot read them)
- `build-wait.sh [--max SEC] [--no-summary] PGID LOG` — one bounded wait for a build started with `set +m; setsid -w geectl local-build build --live … </dev/null >LOG 2>&1 &` (`$!` is PGID); `build-wait.sh --max` default 540 (a 10-minute tool call; pass less under a shorter one), 0 checks once; then `build-summary.sh LOG`; `build-wait.sh --no-summary` for any other local job (`geectl local-build service-run`, a vendor or cargo run; PGID may be its pid): once it is gone, LOG's last line and exit 0 — read its outcome in LOG; exit 0 green · 1 failed · 2 no log · 3 no verdict · 4 still running: repeat the call · 5 usage, or PGID is not a group id
- `soname-check.sh [file.rpm ... | --build-root DIR]` — no args: the newest root under the local-build cache; a root's RPMs are its build's `.build.packages/RPMS`; exit 0 clean · 3 findings · 2 usage or no RPMs
- `scm-snapshot.sh [git-url] [--rev SHA|BRANCH] [--base X.Y.Z] [--pkg NAME] [--update]` — url required unless `--update`, which re-pins `./_service` in place; exit 0 verified · 1 mismatch · 2 usage or a step failed
- `rdeps.sh <pkg-or-substring> [project] [repo] [arch]` — exit 0 listed · 1 no _builddepinfo · 2 usage
- `cone-status.sh <project> [repo] [arch]` — remote-build loop; exit 0 all green · 1 in flight · 2 settled failure · 3 no answer (usage or lookup failed) · 4 QUEUED-STUCK: only scheduled packages left, 30+ min after their last commit and the repo/arch's last finished job, the rest green — not green, report it and check back later
- `obs-wait.py build PRJ PKG [--repos REGEX] [--arches REGEX] [--target PRJ] [--all] [--repo R] [--arch A] [--timeout S] [--recheck S] | request ID [--timeout S] [--recheck S]` — one bounded wait, `obs-wait.py --timeout` default 80, 0 asks once (a long watch is ONE background call with a long `obs-wait.py --timeout`, e.g. 3600, never a shell loop); a build is waited on where `gate.sh --obs-build` judges it (Tumbleweed and Leap 16 on x86_64/aarch64, a repo/arch the link origin disables skipped, `obs-wait.py --target openSUSE:Factory` leaving Leap 16 out; `obs-wait.py --repos/--arches` widen it, `--all` takes every one, `--repo`/`--arch` name exactly one), the rest named as not judged; polls geectl when the event stream is unreachable; the verdict is the exit code and the VERDICT line, never a re-read of `geectl build results`; exit 0 green from the current sources, or accepted · 1 still pending, OBS still running the source service included: repeat the call · 2 settled failure, or declined/revoked/superseded/deleted · 3 no answer (usage, a geectl lookup failed or came back empty, or nothing in scope builds it) — never settled · 4 QUEUED-STUCK: only scheduled arches left, 30+ min after the last commit and the repo/arch's last finished job, the rest green from the current sources · 5 BLOCKED-UPSTREAM: only blocked arches left, the link origin blocked at each too, the rest green — 4 and 5 are not green: report it and move on, never file on them
- `vendor-strip.py TARBALL GLOB... (-o|--output OUTPUT | --dry-run)` — a cargo vendor tarball (tar, zst, xz, gz, bz2: kept as it was); GLOB relative to the vendor root (`vendor/`), `*` inside one path segment, `**` across them; also drops each removed file's key from its crate's `.cargo-checksum.json`, every other member and byte kept; OUTPUT may be TARBALL; refused: a glob matching nothing (one naming a directory gets the `<dir>/**` hint), a crate's `Cargo.toml` or `.cargo-checksum.json`, a kept hard link or symlink to a removed member; only for a file the Linux build would use or that ships (one for another OS or CPU is declared `other-platform` instead), and never named in a spec or `.changes`; exit 0 written (`--dry-run`: listed) · 1 refused, nothing written · 2 usage, or the tarball unreadable or the result unwritten
- `gpg-verify.sh <tarball> <keyring> [signature]` — exit 0 good · 1 bad or unverifiable · 2 usage or unusable input
